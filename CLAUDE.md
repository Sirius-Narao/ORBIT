# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## What ORBIT is

ORBIT (Open Research & Benchmarking Intelligence Toolkit) is a **terminal-first AI/research toolkit**, not a PyTorch clone. Core philosophy: *the user specifies the experiment → ORBIT handles the machinery → ORBIT records the results → the user analyzes and reproduces them.*

**Hard architectural rule: experiments are declarative saved configs, not Python scripts.** The user never hand-writes a `.py` file that builds a `Model`/`Optimizer`/`Trainer` and calls `.run()` — that's ORBIT's own internal engine code (what you're writing in `src/orbit/`), not user-facing. `orbit new` interactively walks the user through configuring dataset/model/optimizer/hyperparams and saves the result as a JSON config; `orbit run <experiment>` loads that saved config and is what actually constructs the `Tensor`/`Model`/`Loss`/`Optimizer`/`Trainer` objects and executes training. Flow: `experiment.json` → ORBIT engine (`core`/`nn`) → results.

On-disk layout (per experiment):
```
.orbits/
└── experiments/
    └── <name>/
        ├── experiment.json   # the saved config
        ├── results/
        └── checkpoints/
```
Example `experiment.json`, corrected schema (resolves the two gaps in the original draft: `loss` is now an explicit field, and the first layer explicitly carries `in_features` since nothing else in the schema states input dimensionality):
```json
{
  "name": "xor_mlp_01",
  "dataset": "xor",
  "model": [
    {"type": "Linear", "in_features": 2, "neurons": 8},
    {"type": "Tanh"},
    {"type": "Linear", "neurons": 1},
    {"type": "Sigmoid"}
  ],
  "loss": "MSE",
  "optimizer": "SGD",
  "learning_rate": 2.0,
  "batch_size": 4,
  "epochs": 3000,
  "seed": 42
}
```
(`mnist` from the original draft doesn't exist in ORBIT yet — see the config-loader v1 scope note below. `optimizer` is `"SGD"` or `"Adam"`, each with optional flat fields at standard defaults: `"momentum"` (SGD only, default `0` = plain SGD) and `"betas"` (a 2-element list, default `[0.9, 0.999]`)/`"eps"` (default `1e-8`) (Adam only); a field meant for the other optimizer makes `load_experiment` raise `ValueError` rather than be silently ignored. `batch_size` defaults to `DataLoader`'s own default, `32`, if omitted. `seed` is optional — omit it for an unseeded/non-reproducible run; when present, `load_experiment` calls `np.random.seed(seed)` before building anything, since `Linear`'s weight init and `DataLoader`'s shuffling both draw from the global NumPy RNG, so this one call fixes both for the whole run. `orbit new`/`orbit copy` both auto-fill a random seed when the user leaves the prompt blank, so an experiment saved through the CLI always has one; only a hand-written or hand-edited `experiment.json` would omit it.) Only the first layer in `model` needs `in_features`; every layer after it infers its input width from the previous layer's `neurons`. An optional `"task"` field (`"binary_classification"`, `"multiclass_classification"`, `"regression_tolerance"`, or `"regression_r2"`, see `TASK_REGISTRY` below) turns on per-epoch accuracy (or, for `regression_r2`, R²) tracking, with an optional `"accuracy_tolerance"` (default `0.5`) for `regression_tolerance`; omit it and only loss (plus gradient norm — see `_gradient_norm` below) is tracked, matching every config written before accuracy tracking existed. An optional `"test_split"` field (float, e.g. `0.2`) holds out a fraction of the dataset for a post-training evaluation pass — see "Planned: normalization, train/test split..." below for the implemented details (`core/dataset.py`'s `train_test_split`/`Subset`, `Results.test_loss`/`test_accuracy`); omit it for training-only behavior, unchanged from before this field existed. An optional `"normalize"` field (`"standard"` or `"minmax"`; absent or `"none"` = off) rescales the **inputs only** with stats fit on the training split — see that same section's item #1.

**Full command surface** (`init`, `new`, `run <experiment>`, `train`, `test`, `list`, `inspect`, `delete`, `compare`, `reproduce`, `copy`, `rename`, `import`, `plotloss`, `plot`, `network`, `sweep create/start/status/compare/export/plot`, and the bare `orbit` REPL are now implemented end-to-end — parser → command → storage/config loader → engine; `new --template` and `sweep reproduce` are still stub):
- `orbit` — opens the interactive ORBIT research environment. Implemented in `cli/repl.py` (`repl()`): prints an ASCII banner, then loops reading lines with `questionary.text(...).unsafe_ask()`, `shlex.split`s each into tokens, and feeds them through the *same* `build_parser()`/`_dispatch()` as the direct CLI — so every subcommand below works identically inside the REPL. `help`/`?` prints `parser.format_help()` plus the REPL-only meta-commands; `exit`/`quit` (or Ctrl-D) leaves; Ctrl-C clears the current line instead of exiting; a `SystemExit` from a bad `argparse` line or any other exception from a command is caught so one bad line can't kill the session. See `tests/cli/test_repl.py`.
- `orbit init` — initializes a new ORBIT project. Implemented in `cli/commands/init.py` (`init_project`): `mkdir(parents=True, exist_ok=True)`s both `.orbits/experiments/` and `.orbits/datasets/`; idempotent and non-destructive, so re-running it on an already-initialized project just backfills whichever directory is missing rather than erroring, printing a warning ("already initialized") instead of the success message in that case.
- `orbit import <csv-path> [--name NAME] [--target COL [COL ...]]` — imports a CSV as a named dataset under `.orbits/datasets/<name>/` (a copy of the CSV plus a `dataset.json` manifest of input/output column names). Implemented in `cli/commands/import_dataset.py`; see "Dataset design reassessment" below for the design and remaining scope limits (CSV + numeric columns only).
- `orbit run` — starts an experiment setup flow (configure dataset/model/optimizer/training settings), then runs it. *(Distinct from `orbit run <experiment>` reproducing a saved config — the same verb covers both "configure then run" and "load then run.")* Both halves exist: `orbit run <experiment>` (load a saved config, `cli/commands/run.py`), and bare `orbit run` with no name (`run_parser`'s `name` is `nargs="?"`), which `_dispatch` handles by calling `create_experiment()` and then running the experiment it just saved. `orbit run <experiment>` trains a full run and reports `results.final_loss`, warning if the run looks stalled (see `_warn_if_stalled` in `cli/parser.py`); when the config sets `"test_split"` it also reports `results.test_loss`/`results.test_accuracy` right after (see "Planned: normalization, train/test split..." below for how that split/evaluation works). **Confirmed decision: `orbit run` keeps this exact behavior (train, then evaluate on the test split when one is configured, in one call) — it is not being renamed or split apart.** See the planned `orbit train`/`orbit test` commands below for the narrower alternatives.
- `orbit new` / `orbit new --template <name>` — creates a new experiment interactively (optionally from a template), still asking the user to configure it. The base flow (no `--template`) is implemented in `cli/commands/new.py`; `--template` is not. The base flow also lets the user opt into per-epoch accuracy tracking (`"Track accuracy?"`, whose choices come straight from `TASK_REGISTRY` — see the config-loader scope note below; picking `regression_tolerance` additionally asks for `"accuracy_tolerance"`, pre-filled `0.5`, and the summary's Task row shows it as `regression_tolerance (±0.5)`), pick input normalization (`"Normalize inputs?"` select: `none`/`standard`/`minmax`, written only when not `none`), set SGD momentum (`"Momentum (0 = plain SGD):"`, asked only when SGD is picked, written only when non-zero — Adam's `betas`/`eps` are JSON-only, never prompted; the learning-rate prompt pre-fills `0.001` for Adam), and always auto-fills a random `seed` if left blank.
- `orbit list` — lists previously recorded experiments. Implemented in `cli/commands/list.py` (`list_experiments`): scans `.orbits/experiments/`, rendering a `rich.table.Table` with one row per experiment directory — name, "done"/"not run" status (based on whether `results/results.json` exists), final loss, and epoch count. Prints a warning instead of a table only when there are neither experiments nor sweeps. **Sweeps:** sweep runs are ordinary experiments, so they're hidden from this table (any name listed in a sweep manifest, via `sweeps/config.py`'s `sweep_membership`) and summarized instead in a separate **Sweeps** table, one row per sweep: name, base, `done/total` runs, the metric it's ranked by (`default_rank_metric`), best run and best value. `orbit list --runs` (`show_runs=True`) lists the runs individually again. `orbit sweep status` has per-run detail.
- `orbit inspect <id>` — shows an experiment's configuration, metrics, recorded info. Implemented in `cli/commands/inspect.py` (`inspect_experiment`): loads `experiment.json` and reuses `new.py`'s `_print_config_summary` table to show it, then prints final loss/epoch count from `results.json` if the experiment has been run, or "Not run yet." if not.
- `orbit compare <id> <id> ...` / `orbit compare --all [--plotloss] [--logscale] [--by METRIC ... | --test]` — compares experiments via metrics/stats/visualizations. **`--by`** ranks them by one or more of `final_loss`/`test_loss`/`accuracy`/`test_accuracy`/`duration_seconds` (a bare `--by` asks via a checkbox; no `--by` means no ranking, the table exactly as before). Several metrics are combined by average rank (see `core/ranking.py` under Experiment orchestration). The overall best row is green, and each metric's best value cell gets that metric's own color plus a `★`, with matching colored "Best <metric> ★ :" lines after the table (`cli/commands/ranking_display.py`). **`--test`** (`test_only=True`; mutually exclusive with `--by`) ranks by the test metrics only (`ranking_display.TEST_METRICS`: `test_loss`, `test_accuracy`, whichever were recorded, others skipped quietly via `test_metrics_for`), i.e. by how well each model generalizes, ignoring how well it fit its training data. With no test metrics at all it warns how to get them (a `test_split`, or `orbit test`) and shows the unranked table. `orbit sweep compare --test` does the same for a sweep. Implemented in `cli/commands/compare.py` (`compare_experiments`): one `rich.table.Table` row per experiment with dataset/loss/optimizer/learning rate/seed/batch size/epochs/final loss, skipping (with a warning) any name that isn't found; `--all` compares every experiment under `.orbits/experiments/` instead of a named list. `--plotloss` additionally overlays every compared experiment's loss curve on one `matplotlib` plot (`visualization.loss.plot_loss_comparison`), saved under `.orbits/comparisons/` (filename is the sorted, `_vs_`-joined experiment names, falling back to `comparison_<n>_experiments.png` once that would exceed 100 characters); `--logscale` renders that comparison plot's y-axis on a log scale (same flag name/meaning as `orbit plotloss`'s, see below). Flag naming follows this codebase's established convention: name a plot flag after the metric (`--plotloss`), never a generic `--plot`.
- `orbit reproduce <id>` — re-runs an experiment from its recorded configuration. Implemented in `cli/commands/reproduce.py` (`reproduce_experiment`): warns up front if the saved config has no `seed` (re-running then isn't expected to match), calls `run_experiment` again, and compares the new `final_loss` to the previously recorded one (`abs(...) < 1e-9`) to report a match or a diff.
- `orbit copy <id>` — creates a new experiment using an existing one's config as defaults, editable. Implemented in `cli/commands/copy.py` (`copy_experiment`): dataset/model/loss/task are copied unchanged from the source (changing those means running `orbit new` from scratch); `normalize`/`optimizer` (plus `momentum` when SGD; Adam's `betas`/`eps` carry over only if the copy stays on Adam)/`learning_rate`/`batch_size`/`epochs`/`test_split`/`seed` are re-prompted with the source's values pre-filled as defaults (`normalize` via a `questionary.select` with `default=` the source's value — flipping only normalization is a one-keystroke ablation) — keeping the source's seed (just hit enter) isolates the effect of a hyperparameter change from random-init/shuffle noise, the same way an ablation study holds everything but one variable fixed; clearing the seed field picks a fresh random one for a genuinely independent run.
- `orbit rename <old_name> <new_name>` — **not in the original command-surface draft**, added alongside `delete`/`copy`/`compare`/`list`/`inspect`. Implemented in `cli/commands/rename.py` (`rename_experiment`): renames the experiment's directory, then rewrites the `"name"` field inside both `experiment.json` and `results.json` (if present) so they stay in sync with the directory `list`/`inspect`/etc. look them up under. Refuses if `old_name`/`new_name` are identical, `old_name` doesn't exist, or `new_name` is already taken.
- `orbit delete <name> [--all]` — **not in the original command-surface draft**, added alongside `rename`/`copy`/`compare`/`list`/`inspect`. Implemented in `cli/commands/delete.py` (`delete_experiments`): `shutil.rmtree`s a named experiment's directory, or every experiment directory under `.orbits/experiments/` when `--all` is passed instead of a name. `--all` also removes every sweep manifest under `.orbits/sweeps/`, since with all runs gone they would only list "missing" runs. Deleting a single run that belongs to a sweep still works, with a warning that the sweep will now show it as missing and a pointer to `orbit sweep delete`. No confirmation prompt — this is a destructive, irreversible operation exposed directly on the CLI, so treat it with the same care as any other `rm -rf`-shaped command when suggesting or scripting its use.
- `orbit plotloss <id> [--logscale]` — **renamed from `orbit plot`** (see the new `orbit plot` bullet immediately below for why). Unchanged behavior otherwise: loss-only, single-experiment. `cli/commands/plotloss.py` (`plot_experiment`) mirrors `inspect_experiment`'s two-guard shape (missing experiment → warn; no `results.json` yet → warn "has not been run yet - nothing to plot (run it first)."), then calls `visualization.loss.plot_loss(results, exp_dir/"results"/f"loss{extension}.png", log_scale=log_scale)` (`extension` is `"_log_scale"` when `--logscale` is passed, so a log-scale and linear plot of the same experiment don't clobber each other) and reports the saved path via `success(...)`. `plot_loss` renders a `matplotlib` line plot (epoch on x, loss on y, ORBIT's `#b0ffb3` accent color) and saves it as a real PNG. `matplotlib` is imported lazily *inside* `plot_loss`/`plot_loss_comparison` and every other `visualization/*.py` plot function, not at module scope, since `cli/parser.py` imports every `cli/commands/*.py` module unconditionally at startup and a top-level import would tax every `orbit` invocation with matplotlib's load cost; the `Agg` (non-interactive) backend is forced since this only ever saves to disk — there's no `--show`/interactive-window flag, deliberately, since `cli/repl.py` keeps one process alive across many commands in a session and backend-switching mid-process is a footgun not worth taking on (`plt.close(fig)` after each save keeps the REPL's long-lived process from leaking figures across repeated calls). See `tests/visualization/test_loss.py`, `tests/cli/test_plotloss.py`.
- `orbit plot [name ...] [--all] [--logscale] [--metrics ...]` — **implemented**, and a *different* command from `orbit plotloss` above: interactively plots one or more experiments' metrics, added per explicit user request superseding the originally-sketched multi-metric design (see "Planned: normalization, train/test split..." item #5 below). `cli/commands/plot.py` (`plot_experiments`): resolves `names`/`--all` the same way `compare_experiments` does (warn + `[]` on no experiments found), then gathers `(name, exp_dir, Results)` for every requested name that exists and has been run, warning+skipping ones that don't (mirrors `compare_experiments`' `plot_candidates` pattern). Which metric(s) to plot — Training loss, Accuracy, Gradient norm, Test loss, Test accuracy — is chosen via a `questionary.checkbox` prompt (same pattern as `import_dataset.py`'s target-column prompt) unless `--metrics` (internal keys: `loss`/`accuracy`/`gradient_norm`/`test_loss`/`test_accuracy`, enforced by argparse's `choices=`) is given to bypass it, e.g. for scripting. Training loss/accuracy/gradient norm plot as line curves (`visualization.loss`/`accuracy`/`gradients`, single line or overlaid-with-legend depending on experiment count); test loss/test accuracy — single scalars per experiment, not per-epoch histories, so they can't be line-plotted the same way — render as **bar charts** instead (new `visualization/test_metrics.py`, one bar per experiment, via a shared `_bar_chart` helper; unlike the line metrics there's no separate single/comparison function since one bar generalizes to N with no code-shape difference). Each metric is filtered to only the experiments that actually have it (an experiment missing `"task"` or never `orbit test`-ed is skipped **for that metric only**, with a `warning()`, not a hard failure) — this is deliberate: experiments in one `orbit plot` call can be heterogeneous (different configs tracking different things). Whether output goes to a single experiment's own `results/` dir (`<exp>/results/<metric>.png`) or to `.orbits/comparisons/` (reusing `compare.py`'s `_comparison_filename`, now extended with an optional `metric=` parameter — default `None` keeps `compare --plotloss`'s existing filenames byte-identical, `plot` passes e.g. `metric="loss"` to get `exp_a_vs_exp_b_loss_log_scale.png`) is decided **once per invocation**, from how many requested experiments actually had *any* results — not re-decided per metric — so a call naming 2 experiments where only 1 turns out to have `test_accuracy` still writes under `.orbits/comparisons/` (just named only for the experiment(s) actually in that particular plot). See `tests/cli/test_plot.py`, `tests/cli/test_compare.py` (`_comparison_filename`'s new `metric=` tests), `tests/visualization/test_accuracy.py`, `test_gradients.py`, `test_test_metrics.py`.
- `orbit network <name> [--sample N] [--output PATH] [--show]` — **implemented** (phase 1 of the black-box visualization round, see "Black-box visualization round" below). Draws the model itself as a PNG. `cli/commands/network.py` (`network_experiment`) rebuilds the experiment with `load_experiment(config)` and loads its checkpoint if there is one. With no checkpoint it draws the seeded initial weights, warns, and titles the plot "(untrained — initial weights)", so an experiment can be looked at before it's run. It then `forward_trace`s the whole training split (after split/normalization, the same data the model trained on). Without `--sample`, nodes show the **mean** activation over the training set. With `--sample N` they show training row N, and the subtitle shows its input (marked "(normalized)" when the config normalizes), the prediction and the target. Node colors are normalized per column against that column's min/max **over the whole training set**, not the sample's own range. Wide columns show their most active units (`rank_nodes`). The default output is `<exp>/results/network.png` (`network_sample<N>.png` with `--sample`). Shared helpers `load_trained_experiment`/`training_arrays` live in the same module for the later phases. **`--show`** also opens a window: `visualization/backend.py`'s `pyplot(show)` picks TkAgg, falling back to Agg with a warning if Tk is unavailable. `_dispatch(args, in_repl=False)` gained an `in_repl` flag that `cli/repl.py` sets, and `_resolve_show` refuses `--show` inside the REPL with a warning (the file is still saved), since switching backends in the REPL's long-lived process is the footgun the plotting code's forced `Agg` avoids. See `tests/cli/test_network.py`, `tests/visualization/test_network_diagram.py`, `tests/nn/test_introspection.py`, and the `network` cases in `tests/cli/test_parser.py`/`test_repl.py`.
- `orbit train <experiment>` / `orbit test <experiment>` — **implemented.** `train` (`cli/commands/train.py`, `train_experiment`) mirrors `run_experiment` exactly except it calls `experiment.run(skip_test=True)` (a new optional parameter on `Experiment.run`, default `False`, preserving `orbit run`'s existing behavior untouched) so no test-set evaluation happens even when `"test_split"` is configured. Both `orbit run` and `orbit train` now also save a checkpoint of the trained model's weights (`storage/artifacts.py`'s new `save_checkpoint`, see below) right after `save_results`, since `orbit test` needs one regardless of which command produced it. `test` (`cli/commands/test.py`, `test_experiment`) evaluates an **already-trained** experiment on demand, without retraining: it loads `experiment.json` with the exact same try/except-raise-`FileNotFoundError` pattern `run_experiment`/`train_experiment` use (so a nonexistent experiment fails identically across all three), then warns and returns `None` if no checkpoint has been saved yet (`storage/artifacts.py`'s `checkpoint_exists`) or if the config has no `"test_split"` field (nothing to evaluate against); if the config has no `"seed"` it warns (mirroring `orbit reproduce`'s equivalent warning) but still proceeds. On success it calls `load_experiment(config)` again to reconstruct the identical dataset/train-test split (same seeded-RNG-replay convention `orbit reproduce` already relies on), overwrites the freshly-initialized model's weights via `load_checkpoint`, calls `Trainer.evaluate(...)` directly, and persists the resulting `test_loss`/`test_accuracy` back into `results.json` (`load_results`/`save_results`) so a later `orbit inspect` reflects the fresh evaluation. See `tests/cli/test_train.py`, `test_test.py`, `tests/storage/test_artifacts.py`, and the added cases in `tests/core/test_experiment.py`/`tests/cli/test_parser.py`/`test_run.py`.
- `orbit sweep create/start/status/compare/export/plot/delete` — **implemented (v1, grid search only)**; `sweep reproduce` is deferred, since `orbit reproduce <run>` already works per run. Code lives in `cli/commands/sweep.py` (`create_sweep`/`start_sweep`/`sweep_status`/`compare_sweep`/`export_sweep`/`plot_sweep`) on top of pure logic in `sweeps/` (`config.py`, `generator.py`, `aggregator.py`, none of which import `cli/`). `runner.py`/`scheduler.py`/`analyzer.py` are still empty stubs; orchestration lives in the CLI because it reuses `run_experiment`.
  - **Layout:** `.orbits/sweeps/<sweep>/sweep.json` holds `name`, `base` (the base experiment's name), `base_config` (a snapshot of its `experiment.json` at create time, so the sweep survives later edits or deletion of the base), `grid` (`{field: [values]}`), and `runs` (`[{"name", "params"}]`). Each run is an **ordinary experiment** at `.orbits/experiments/<sweep>_001`, `_002`, … (zero-padded to at least 3 digits), so `inspect`/`test`/`reproduce`/`plot`/`compare` work on a single run unchanged; the cost is that runs also show up in `orbit list`.
  - **`create <name> --base <exp>`** prompts with a `questionary.checkbox` over `SWEEPABLE_FIELDS` (`learning_rate`, `optimizer`, `momentum`, `batch_size`, `epochs`, `seed`, `normalize`, `test_split`, plus the architecture fields `hidden_width`/`hidden_depth`/`activation`, see below). Choice fields then get a checkbox, number fields a comma-separated text prompt pre-filled with the base value. It prints a summary (and notes when `seed` isn't varied, i.e. every run shares the base seed), refuses if any generated run name already exists, asks `questionary.confirm`, then writes `sweep.json` plus every run's `experiment.json`. Nothing is trained yet.
  - **Grid expansion** (`generator.expand_grid`): `itertools.product` in grid-key order over a deep copy of `base_config`, then normalized — optimizer options that don't apply to the chosen optimizer are dropped (via `core/config.py`'s `OPTIMIZER_OPTIONS`, so e.g. Adam never gets `momentum`, which `load_experiment` would reject) and `normalize: "none"` is removed. Combinations that become identical are deduplicated, so `SGD/Adam × momentum [0, 0.9]` is 3 runs, not 4. A run's `params` records only values that took effect.
  - **Architecture fields** (`ARCHITECTURE_FIELDS` in `sweeps/config.py`): `hidden_width` (int, ≥ 1, units per hidden layer, uniform across layers), `hidden_depth` (int, ≥ 0, number of hidden layers) and `activation` (`ReLU`/`Tanh`/`Sigmoid`; Softmax isn't offered, it's an output activation). They're **virtual**: never written as `experiment.json` keys, they rewrite its `"model"` list, so every run stays a standard experiment that `build_model`/`inspect`/`test`/`reproduce` handle unchanged. `generator.py` reads a model as `[hidden part][head]`, where the **head** is the last `Linear` plus any activations after it (e.g. `Linear(->1), Sigmoid`) and is always kept as is, so the output width/activation the dataset and task need never change. `describe_architecture(model)` gives the base values (first hidden width, number of hidden Linears, first hidden activation), which also pre-fill the `create` prompts. `apply_architecture(model, hidden_width, hidden_depth, activation)` rebuilds `depth × [Linear(width), activation]` + head; any field not swept keeps the base's value (a tapered base like 128 → 64 contributes its first width), and `in_features` moves to whichever layer is now first (the head's Linear at depth 0, i.e. a linear model). At `hidden_depth` 0, `hidden_width`/`activation` can't matter, so they're dropped from `params` and the duplicates collapse, like `momentum` for Adam: width [2, 4, 8] × depth [0, 1, 2] × activation [Tanh, ReLU] is 13 runs, not 18. A base with no hidden layer swept on depth without `hidden_width` raises `ValueError` ("also vary hidden_width"), which `create` reports without writing anything. `FIELD_MINIMUMS` makes the `create` number prompts reject e.g. width 0.
  - **Status is never stored**: it's derived from disk (`aggregator.run_status`: `results/results.json` → `done`; no `experiment.json`, e.g. after `orbit delete` → `missing`; otherwise `pending`). **`start`** therefore resumes for free: it skips `done` runs, reports `missing` ones, and wraps each `run_experiment` call in its own `try/except Exception`, so one failing combination is reported and the rest continue. Ctrl-C needs no handling; the next `start` picks up.
  - **`compare [--by METRIC ... | --all | --test]`** ranks runs with the same multi-metric ranking and coloring as `orbit compare --by` (default: `test_loss` if the base config or grid has `test_split`, else `final_loss`; a bare `--by` prompts). **`--all`** (`all_metrics=True`; mutually exclusive with `--by` via an argparse group) ranks by every **quality** metric (`_ALL_METRICS`: every `RANK_METRICS` entry except `duration_seconds`) that at least one run recorded, quietly skipping the rest (e.g. test metrics without a test split, accuracy without a task) since none were asked for by name. Duration is excluded deliberately: on small/fast runs durations differ only by timing noise (milliseconds), and under average-rank aggregation that noise got an equal vote, pushing the lowest-loss configuration of a test sweep from 1st to 5th. It's still available explicitly via `--by ... duration_seconds`. `orbit compare`'s own `--all` keeps its existing meaning, "every experiment". **`--test`** ranks by the test metrics only, as `orbit compare --test` does; `--by`/`--all`/`--test` are one mutually exclusive argparse group, and `compare_sweep` raises `ValueError` if called with more than one of `by`/`all_metrics`/`test_only`. When the grid has more than one `seed`, it adds a "Grouped over seeds" table: groups of runs differing only by seed, ranked by average rank over their *mean* metrics, each cell shown as mean ± std (population `np.std`), since a single seed's win can be init/shuffle luck. Losses print with `.4g`, not `.4f`, so near-zero losses stay distinguishable.
  - **`export [--output PATH]`** writes a stdlib-`csv` file (default `<sweep_dir>/results.csv`): `run`, each grid field, `status`, `final_loss`, `test_loss`, `test_accuracy`, `duration_seconds`, with empty cells for values that don't exist yet.
  - **`plot [--logscale] [--metrics ...]`** delegates to `plot_experiments` for the `done` runs, with `comparisons_root=<sweep_dir>/plots`. ### Dataset design reassessment (opened by the `be3a0cb` commit note — read before touching `orbit import`, `DATASET_REGISTRY`, or `cli/commands/new.py`'s dataset/shape prompts)

Building `new`/`run` end-to-end against the v1 config loader surfaced three concrete gaps, in the committer's own words, that should shape the next round of design rather than being patched over individually:

1. **Only `"xor"` exists in `DATASET_REGISTRY`; there's no way to bring in real data.** **Done, CSV only.** `DATASET_REGISTRY` itself is untouched (still just the hardcoded `"xor"` factory) — imported datasets are a separate, disk-backed lookup, not merged into that dict. `src/orbit/storage/datasets.py` (new) mirrors `storage/experiments.py`'s shape: `DATASETS_ROOT = .orbits/datasets`, `dataset_dir`/`save_dataset_manifest`/`load_dataset_manifest`/`dataset_exists`/`list_imported_dataset_names`. `orbit import <csv> [--name NAME] [--target COL ...]` (`cli/commands/import_dataset.py`) reads the CSV header, prompts (`questionary.checkbox`) for the target/output column(s) if `--target` isn't given (every other column becomes input automatically), copies the CSV to `.orbits/datasets/<name>/data.csv`, and writes a `dataset.json` manifest of `input_columns`/`output_columns`. `build_dataset` (`core/config.py`) falls back to a new `_load_csv_dataset` (stdlib `csv` module, no new dependency) when a name isn't in `DATASET_REGISTRY` but `dataset_exists` on disk — reuses `TensorDataset` directly, no new `Dataset` subclass. New `list_dataset_names()` (`= list(DATASET_REGISTRY) + list_imported_dataset_names()`) feeds `orbit new`'s dataset picker, so imported datasets appear alongside `"xor"` with no other changes needed there (`build_model`'s shape checks, the stalled-run warning, etc. all already work against any `Dataset`). **Scope, deliberately narrow**: CSV only, numeric columns only (a non-numeric cell raises `ValueError` naming the column) — no categorical encoding, no missing-value handling, no `orbit list`/`orbit inspect` for datasets. Note: `orbit/core/__init__.py` deliberately does **not** re-export `load_experiment` — import it from `orbit.core.config`. `config.py` is the glue layer that imports `orbit.nn`/`orbit.storage`, and both of those import `orbit.core` back, so re-exporting it from the bottom-layer `orbit.core` package made `import orbit.nn` (e.g. running `tests/nn/test_optimizers.py` on its own) fail with a circular-import `ImportError`. (That re-export was also why `storage/__init__.py` used to have to import `.datasets` before `.experiments`; the order no longer matters, but keep it.) See `tests/storage/test_datasets.py`, `tests/core/test_config.py` (`test_build_dataset_resolves_an_imported_csv_dataset` etc.), `tests/cli/test_import.py`, and `tests/cli/test_new.py::test_create_experiment_dataset_picker_includes_imported_datasets`.
2. **Datasets are too implicit — ORBIT doesn't know a dataset's input/output feature counts.** **Done, both directions.** `Dataset`/`TensorDataset` (`core/dataset.py`) expose `input_shape`/`output_shape` properties (plain ints — the per-sample feature count, e.g. `self.X.shape[-1]`; the base `Dataset` raises `NotImplementedError`, matching the existing `__len__`/`__getitem__` convention). `build_model` (`core/config.py`) takes an optional `dataset` argument and raises `ValueError` if the first `Linear` layer's declared `in_features` doesn't match `dataset.input_shape`, **and** (symmetrically, checked once the layer loop finishes) if the last `Linear` layer's `neurons` doesn't match `dataset.output_shape` — `in_features` is tracked across the loop and, since activations don't change it, still holds the final output width by the time the loop ends. Neither check auto-fills a missing value — `in_features` is still required explicitly in the config, per the documented `experiment.json` schema (a missing `in_features` is its own, separate `ValueError`, checked before the input-mismatch check). `orbit new` (`cli/commands/new.py`) builds the chosen dataset immediately after the user picks its name, prints a line like `Dataset 'xor': 2 input feature(s), 1 output feature(s)`, passes `dataset.input_shape` into `_ask_model_layers` to fill the first `Linear` layer's `in_features` directly (no prompt for it at all), and — since the *output* width isn't known until the user says "Done" — calls `build_model(layers, dataset)` at that point purely to validate; on `ValueError` it prints the message and loops back to "Add a layer" instead of saving a broken config, letting the user add a corrective layer. See `tests/core/test_dataset.py` (shape properties), `tests/core/test_config.py` (`build_model`'s input- and output-shape tests), and `tests/cli/test_new.py` (`test_create_experiment_fills_in_features_from_dataset_without_prompting`, `test_create_experiment_rejects_output_shape_mismatch_and_lets_user_fix_it`).
3. **CLI output isn't appealing or informative enough.** **Done, pass 1 (training + interactive flows only).** A new top-level `src/orbit/ui.py` (sibling to `cli/`, `core/`, `nn/`, `storage/` — deliberately *not* placed under `cli/`, since `nn/training/trainer.py` needs the same console/tty logic and `nn/` must never depend on `cli/`) is the shared styling module: a `rich.console.Console` instance, `info`/`success`/`warning`/`error` helpers (thin `console.print(msg, style=...)` wrappers), `is_tty()` (checked fresh on every call, never cached, so pytest's `capsys` swap of `sys.stdout` is detected correctly regardless of import order), and a shared `questionary.Style` (`PROMPT_STYLE`) so prompts and `rich` output share one look. `new.py`/`import_dataset.py`/`parser.py` route their prompt/print calls through this module instead of bare `print()`/unstyled `questionary` calls; `new.py` additionally renders a `rich.table.Table` summary of the full experiment config right before saving `experiment.json`. `Trainer.fit()`'s verbose path (see below) got a live `rich.progress.Progress` bar. `rich` is now a dependency (`pyproject.toml`). Scope was deliberately narrow: `list`/`inspect`/`compare`/etc. stayed untouched stub files at the time (nothing to tabulate yet — they were built out later, see below), and no ASCII banner/logo was added yet (also added later, once the bare `orbit` interactive REPL existed). No dedicated tests were added for `ui.py` itself (it's plain print/style wrappers); `tests/cli/test_new.py`/`test_parser.py`'s existing `capsys` substring assertions were re-verified to still pass, since `rich`'s `Console` resolves `sys.stdout` dynamically at print time and auto-suppresses ANSI codes once the stream isn't a real terminal. **Update (`00b5a1c`): the palette was reworked** from `info`/`success`/`warning`/`error`'s original cyan/green/yellow/red style names to a softer custom set of hex colors — `info` and the shared `PROMPT_STYLE` accents use `#ffeab0` (warm gold), `success` uses `#b0ffb3` (soft green), `warning` uses `#d6b0ff` (soft purple — no longer yellow), and `error` uses `#ffb0b0` (soft red) — plus a `rich.theme.Theme` (`THEME`, passed into the module's `Console`) that overrides `rich`'s own internal style names (`bar.back`/`bar.complete`/`bar.finished`/`bar.pulse`, `progress.percentage`/`progress.elapsed`/`progress.remaining`) so `Trainer.fit()`'s progress bar picks up the same palette automatically instead of `rich`'s magenta/pink/yellow/cyan defaults, with no per-column style plumbing needed in `trainer.py`. **Update: fixed a Windows encoding crash in the REPL banner.** `ui.py`'s `Console` is constructed with `legacy_windows=False`, and `sys.stdout`/`sys.stderr` are `.reconfigure(encoding="utf-8", errors="replace")`'d at module import time (wrapped in `try/except (AttributeError, ValueError)` since not every stdout stand-in, e.g. pytest's `capsys`, supports `.reconfigure()`). Without both: whenever stdout isn't attached to a real Windows console (piped through Git Bash/mintty, redirected to a file, wrapped by another process), Windows' PEP 528 UTF-8 console handling doesn't apply, Python falls back to the system locale's codepage (commonly `cp1252`), and any of this module's own non-`cp1252` output — `cli/repl.py`'s box-drawing banner and em dashes chief among them — raised a bare `UnicodeEncodeError` and crashed the whole REPL before a single prompt was shown. Both fixes are necessary: `legacy_windows=False` alone still crashes one layer down (`rich` falls through to a plain `file.write()` that still hits the same `cp1252` codec); the UTF-8 reconfigure alone still crashes inside `rich`'s legacy Win32-console code path. Verified fixed under both a real PowerShell session and Git Bash. ### Planned: normalization, train/test split, `orbit train`/`orbit test`, regression accuracy, and multi-metric visualization (all implemented — kept as the design record)

Opened 2026-09-20 by explicit user requirement (not a code-driven gap like the dataset reassessment above): normalize dataset inputs, hold out a test split, add dedicated train/test commands, broaden accuracy beyond classification (e.g. a wine-quality-style regression dataset), and plot metrics beyond loss. Six requirements below, several with a real build-order dependency on each other — read the "Build order" note at the end before picking one up in isolation. All of #1–#5 are now done.

1. **Input normalization.** **Done.** Optional config field `"normalize"`: `"standard"` (z-score, mean 0 / std 1 per feature) or `"minmax"` (per-feature `[0, 1]`); absent or `"none"` = off, so every existing `experiment.json` and test fixture behaves byte-for-byte as before. **Inputs (X) only** — confirmed with the user: targets stay in their original units so losses/test losses stay comparable across normalized and unnormalized runs, and 0/1 classification labels are never touched. `core/dataset.py` gained `NORMALIZE_METHODS`, `fit_normalizer(X, method) -> stats` (per-column stats; a zero std/range — a constant feature — is replaced by 1 so it maps to zeros instead of NaN; unknown method → `ValueError`), `apply_normalizer(X, stats)`, and `NormalizedDataset(Dataset)`, a generic view (like `Subset`) that applies the stats to `x` in `__getitem__` and delegates everything else — deliberately not a flag on `TensorDataset`/`Subset`, which are used unnormalized throughout `tests/`. `load_experiment` (`core/config.py`) fits the stats on the **train split only** right after `train_test_split` (gathering train rows generically via `train_dataset[i][0]`), then wraps both train and test datasets with those same stats — fitting on train+test would leak test-set information. With no `"test_split"`, the whole dataset is the training set. **Stats are never persisted**: `orbit test` rebuilds via `load_experiment(config)`, which replays the seeded split and so re-derives identical stats (proven by `tests/integration/test_normalization.py`, where `orbit test`'s test loss matches `orbit run`'s exactly); unseeded configs already get the "may not reproduce" warning. `orbit new` adds a `"Normalize inputs?"` select, `orbit copy` re-prompts it with the source's value as `default=` (confirmed with the user — easy normalization-on/off ablation), and `_print_config_summary` shows a `Normalize` row (so `orbit inspect` shows it too). Also fixed `TensorDataset.__init__`'s misleading "Normalizing inputs" comment (it's only list/`Tensor` → ndarray coercion). Smoke-tested on a CSV with one feature in `[0, 1]` and one in `[0, 1000]`: unnormalized training stalled flat (the large feature saturates `Tanh`), `standard` reached ~150× lower loss. See `tests/core/test_dataset.py` (hand-computed normalizer checks), `tests/core/test_config.py` (train-only fitting, `"none"` ≡ absent, invalid value raises), `tests/cli/test_new.py`/`test_copy.py`, `tests/integration/test_normalization.py`.
2. **Train/test split.** **Done.** New optional config field `"test_split"` (float, e.g. `0.2`): key absent means no split at all, training on the full dataset exactly as before this field existed (this matters because forcing every dataset through an 80/20 split would make tiny fixtures like the 4-row `"xor"` dataset degenerate — 3 train rows, 1 test row — so opting in has to stay a per-experiment choice, not a new default); key present with `null`/no value defaults to `0.2`; key present with a float uses that ratio. `core/dataset.py` gained `Subset(Dataset)` (a generic index-based view over any `Dataset`, not array-based, so it works for CSV-imported datasets too) and `train_test_split(dataset, test_split) -> (Subset, Subset)`, which draws from the global `np.random` RNG (`np.random.permutation`) the same convention `DataLoader`'s shuffle already uses, rounding (not truncating) the test-row count so a 4-row dataset at the default 0.2 gets a non-empty 3/1 split, and raising `ValueError` if either resulting split would be empty. `load_experiment` (`core/config.py`) splits right after building the dataset and before building the model — same seeded RNG stream `load_experiment` already seeds via `"seed"`, so re-running a seeded experiment (`orbit reproduce`) reconstructs the identical split rather than needing row indices persisted separately; an unseeded config with `"test_split"` set gets the same "not expected to reproduce" caveat `orbit reproduce` already warns about for training. `nn/training/trainer.py` gained `Trainer.evaluate(model, loss_fn, dataloader, accuracy_fn=None) -> (loss, accuracy)` (forward pass only — no `zero_grad()`/`backward()`/`optimizer.step()` — brackets the pass in `model.eval()`/`model.train()`); `Experiment` (`core/experiment.py`) takes an optional `test_dataloader` and, when given one, calls `trainer.evaluate(...)` right after `trainer.fit(...)` finishes, folding the result into two new `Results` fields, `test_loss`/`test_accuracy` (both `Optional[float]`, default `None`, round-tripped by `to_dict`/`from_dict` same as the other optional fields). `orbit run`'s CLI output (`cli/parser.py`) and `orbit inspect` (`cli/commands/inspect.py`) both print the test loss/accuracy when present, and `orbit new`/`orbit copy` (`cli/commands/new.py`/`copy.py`) prompt for `"Test split fraction (0-1, blank = no split)"` alongside the other hyperparameters (blank omits the key entirely, matching the "absent = no split" config semantics; `copy.py` pre-fills the source experiment's value as the default, same as its other hyperparameter prompts). Every config without a `"test_split"` key is unaffected — `test_dataloader` stays `None`, `Results.test_loss`/`test_accuracy` stay `None`, byte-for-byte the same behavior as before this field existed. See `tests/core/test_dataset.py` (`Subset`/`train_test_split`), `tests/core/test_config.py` (`load_experiment` with `"test_split"` set, including the null-defaults-to-0.2 case), `tests/nn/test_trainer.py` (`evaluate()`), `tests/core/test_experiment.py`, `tests/core/test_results.py`, `tests/integration/test_reproducibility.py` (seeded split reproducibility), and `tests/cli/test_new.py`/`test_copy.py`/`test_parser.py`/`test_inspect.py` for the CLI-facing pieces.
3. **`orbit train` / `orbit test` commands — `orbit run` stays exactly as it is.** **Done.** `orbit run <experiment>` was **not** renamed and **not** split apart, per the confirmed decision — it still loads a config, trains, and evaluates on the test split (when `"test_split"` is set), all in one call. Two new commands were added alongside it:
   - `orbit train <experiment>` (`cli/commands/train.py`) — training only, no test-set evaluation; for fast iteration while tuning hyperparameters. Calls the new `Experiment.run(skip_test=True)` (additive parameter, default `False`, so `orbit run`'s own `experiment.run()` call is untouched) instead of duplicating `Results`-building logic.
   - `orbit test <experiment>` (`cli/commands/test.py`) — evaluates an **already-trained** experiment's saved model against its held-out test split, on demand, without re-training. Guards (each prints a warning and returns `None`): experiment not found; no checkpoint saved yet; config has no `"test_split"`. If the config has no `"seed"` it warns (same "may not reproduce" caveat as `orbit reproduce`) but still proceeds. On success it calls `load_experiment(config)` again — reconstructing the identical seeded train/test split — loads the checkpoint's weights into the freshly-built model (overwriting its throwaway random init), calls `Trainer.evaluate(...)` directly, and persists `test_loss`/`test_accuracy` back into `results.json` so `orbit inspect` reflects the fresh number.

   `orbit test`'s prerequisite — **model checkpointing**, since `Results` never recorded trained weights and `storage/artifacts.py` was a 0-byte stub — is now built, minimally as scoped: `storage/artifacts.py` gained `save_checkpoint(name, model, root)`/`load_checkpoint(name, model, root)`/`checkpoint_exists(name, root)`/`checkpoint_path(name, root)`, saving one `.npz` per experiment at `.orbits/experiments/<name>/checkpoints/model.npz`, keyed by each parameter's `Module.named_parameters()` name (e.g. `"0.weight"`, `"2.bias"`) rather than positional order — the architecture itself is never re-saved, since `experiment.json`'s `"model"` list plus `build_model` already reconstructs it byte-for-byte before a checkpoint is loaded back in. Both `orbit run` and `orbit train` call `save_checkpoint` right after `save_results`, so `orbit test` works no matter which command produced the trained weights. `nn/training/trainer.py`'s `Trainer.evaluate(...)` (built for #2's post-training test-set pass) is reused as-is by `orbit test`, accessed via `experiment.trainer.evaluate(...)` on the freshly reconstructed `Experiment`. See `tests/storage/test_artifacts.py`, `tests/cli/test_train.py`, `tests/cli/test_test.py`, and the added cases in `tests/core/test_experiment.py` (`run(skip_test=True)`), `tests/cli/test_parser.py` (dispatch), and `tests/cli/test_run.py` (checkpoint side effect).
4. **Regression accuracy metrics.** **Done.** Two new task types for continuous targets (e.g. an imported wine-quality CSV), both plain functions in `core/metrics.py` registered in `TASK_REGISTRY`:
   - `"regression_tolerance"` → `regression_tolerance(y_pred, y_true, tolerance=0.5)`: fraction of samples whose every output is within `tolerance` of the target (the boundary counts). The tolerance lives in a new optional config field `"accuracy_tolerance"` (default `0.5`, confirmed with the user — with integer scores it means "rounds to the correct score"); `build_accuracy_fn(task, tolerance)` binds it with `functools.partial`. `orbit new` asks for it (pre-filled `0.5`) only when this task is chosen; `orbit copy` carries it over together with `"task"`.
   - `"regression_r2"` → `r2_score(y_pred, y_true)`: `1 − SS_res/SS_tot` per output column, averaged over columns; a constant-target column scores 1.0 if exact else 0.0 (scikit-learn's convention) instead of dividing by zero.

   Two design decisions, both confirmed with the user or forced by the math:
   - **Whole-pass metric computation.** `Trainer` used to average `accuracy_fn` per batch (batch-size-weighted). That's exact for classification accuracy but wrong for R², which isn't a per-sample average (and a 1-row batch has no R² at all). `_run_epoch`, `evaluate`, and `_evaluate_with_progress_bar` now collect every batch's predictions/targets and call `accuracy_fn` **once** on the concatenation (via `_whole_pass_metric`). Classification numbers are unchanged by this (an overall mean equals the weighted mean of batch means); loss is still averaged per batch. The two old tests that pinned per-batch averaging with canned stub values were rewritten to assert the single whole-epoch call instead.
   - **R² reuses the accuracy slot, labeled by task** (confirmed with the user, instead of separate `r2_history`/`test_r2` fields): R² lives in `accuracy_history`/`test_accuracy` (one task per experiment). `Experiment(..., task=, accuracy_tolerance=)` records `"task"` (and `"accuracy_tolerance"`) in `Results.hyperparams` — only when set, so existing hyperparams are unchanged. `metrics.metric_label(task)` (`"R²"` vs `"Accuracy"`) and `metrics.format_metric(value, task)` (`"0.9123"` vs `"91.23%"`) drive every display: `orbit run`/`orbit test` output (`Test R²: 0.7266`, via `cli/parser.py`'s `_report_test_metrics`), `orbit inspect`, `orbit list` (column now "Final Accuracy / R²"), and plot axis labels/titles (`visualization/accuracy.py`'s `accuracy_axis_label`: the shared label when all plotted experiments agree, "Accuracy / R²" when mixed; also used by `plot_test_accuracy`). An unknown/absent task — e.g. an old `results.json` — falls back to Accuracy/percent, so older results display exactly as before. `orbit plot`'s checkbox labels are now "Accuracy / R²"/"Test accuracy / R²"; the `--metrics` keys are unchanged.

   Smoke-tested on a synthetic wine-quality-style CSV (integer 3–9 target, features on 0–1 / 0–300 / 8–14 scales, `"normalize": "standard"`): test R² 0.7266 (reproduced exactly by `orbit test`), tolerance accuracy 65% on the test split. See `tests/core/test_metrics.py`, `tests/nn/test_trainer.py` (whole-epoch call; exact R² with 1-row batches), `tests/core/test_config.py`, `tests/cli/test_new.py`/`test_copy.py`/`test_parser.py`/`test_inspect.py`/`test_list.py`, `tests/visualization/test_accuracy.py`.
5. **Multi-metric visualization.** **Done, with a different design than originally sketched below** (superseded by an explicit user request left as a note on the commit that added `orbit train`/`orbit test`, once that request was implemented — see the command surface above for the full `orbit plot`/`orbit plotloss` description). The design *originally* sketched here — per-metric CLI flags on `orbit plot` (`--accuracy`, `--gradnorm`) and on `orbit compare` (`--plotaccuracy`/`--plotgradnorm` siblings to `--plotloss`) — was **not** built; instead, the existing `orbit plot <experiment> [--logscale]` was renamed to `orbit plotloss` (unchanged behavior) and a new `orbit plot [name ...] [--all] [--metrics ...]` was added that **interactively** asks which metric(s) to plot (`questionary.checkbox`, matching `import_dataset.py`'s prompt pattern) rather than one flag per metric, and accepts as many experiment names as needed (or `--all`) in one call rather than requiring `compare` for multi-experiment overlays. The "name a plot flag after the metric, never a generic `--plot`" convention noted below was about `compare`'s per-metric *flags* specifically (`--plotloss`) — it doesn't conflict with a `plot` *command* that itself selects metrics interactively; `orbit compare --plotloss` itself is untouched. `visualization/accuracy.py`/`gradients.py` were built matching `loss.py`'s exact shape (`plot_<metric>`/`plot_<metric>_comparison`, line plots). `test_loss`/`test_accuracy` (scalar per experiment, not per-epoch histories, so no line to plot) got their own new module, `visualization/test_metrics.py` (`plot_test_loss`/`plot_test_accuracy`), rendering **bar charts** instead — one bar per experiment via a shared `_bar_chart` helper, no separate single/comparison split needed since a bar chart already generalizes from 1 to N experiments. `weights.py`/`terminal.py` remain out of scope, unchanged from the original note — nothing tracks weight history yet, and `terminal.py`'s ASCII/terminal-rendered-plot purpose is a different, still-unstarted feature. Regression metrics (#4) reuse this same `orbit plot` through the existing `accuracy`/`test_accuracy` entries, with task-aware axis labels rather than new metric keys.

**Build order**: all five items are done. A regression CSV like wine quality should usually combine #1 and #4 (`"normalize"` plus a regression `"task"`).

## Architecture

### The autograd engine (`src/orbit/core/`)

This is the heart of the project and the most mathematically load-bearing code.

- **`tensor.py`** — `Tensor` wraps a NumPy array plus graph metadata (`operation`, `parents`, `requires_grad`, `grad`). Every operator (`__add__`, `__mul__`, `__matmul__`, `.relu()`, `.softmax()`, etc.) builds a new output `Tensor` and attaches a closure to `out._backward` that knows how to route gradients to that op's specific parents. `.backward()` just delegates to `autograd.backward()`.
- **`autograd.py`** — the actual differentiation engine, deliberately kept simple and heavily comment-documented (treat the comments as intentional teaching material, not clutter to strip out). Key pieces:
  - `build_topological_order(root)` — DFS over `parents` to produce a topological ordering of the graph.
  - `backward(root, gradient=None)` — seeds `root.grad` (defaults to `1` for a scalar) and walks the topological order in reverse, calling each node's `_backward`.
  - `accumulate_gradient(tensor, gradient)` — adds (not overwrites) into `tensor.grad`, since a tensor may be reused in multiple graph paths (e.g. `y = x * x`).
  - One `backward_<op>` function per operation (add/sub/mul/div/matmul/pow/neg/sum/mean/relu/sigmoid/tanh/softmax, plus a fused `backward_cross_entropy` for softmax+CCE).
- **Known, intentional limitations of v0.1**: backward rules generally assume compatible shapes (no broadcasting) — this is documented, not a bug to silently "fix" by adding broadcasting logic unless asked. The one exception is `backward_add`, which *does* un-broadcast via the `unbroadcast(gradient, shape)` helper (sums a gradient back down to a parent's original shape when forward-pass broadcasting stretched it) — this exists specifically so `Linear`'s `x @ weight + bias` works with a batched input and a 1D bias. `backward_matmul`, `backward_multiply`, etc. still assume both operands already have compatible/equal shapes going in.
- `tensor.py` imports from `autograd.py` with a `try/except ImportError` fallback (relative import, then absolute `orbit.core.autograd`) — preserve this pattern if editing those imports, it's there to let files be run standalone via `python -m orbit.core.tensor` as well as imported as a package.

### The NN layer (`src/orbit/nn/`)

- **`parameter.py`** — `Parameter(Tensor)`, identical to `Tensor` except `requires_grad=True` by default. Marks "this tensor is a trainable weight."
- **`module.py`** — `Module` base class, PyTorch-inspired: `register_parameter`/`register_module` build `_params`/`_modules` dicts; `parameters()`/`named_parameters()`/`modules()`/`named_modules()` recurse through the tree; `forward()` must be overridden by subclasses; `__call__` dispatches to `forward()`; `zero_grad()`, `train()`/`eval()` propagate through submodules.
- **`layers/linear.py`** — `Linear(Module)`: `x @ weight + bias`. It uses `register_parameter` for both `weight` and `bias`, consistent with the `Module` registration pattern used elsewhere (e.g. in tests' `MLPDummy`), so both show up in `.parameters()`. `weight` is Xavier/Glorot-initialized (`scale = sqrt(2 / (in_features + out_features))` times `randn`) rather than raw `np.random.randn` — unscaled init lets a `Linear`'s output variance grow with `in_features`, which saturates `Tanh`/`Sigmoid` on wide layers (e.g. 120 units) and kills gradient flow before training starts; this was found and fixed after a wide (120-120-1) XOR model trained flat at loss≈0.25 (the exact MSE of a model stuck outputting ≈0.5 everywhere) for 10,000 epochs. `bias` stays zero-initialized (standard practice, no equivalent saturation risk).
- **`introspection.py`** — read-only views of a `Sequential` for the visualization code, in pure numpy with no matplotlib. A model is seen as **columns of nodes**: the input features, then one column per `Linear` (its output units), with any activations directly after a `Linear` applied to that column. `network_structure(model) -> [LayerInfo(key, in_features, out_features, activation)]` (`activation` is the class name, `None`, or `"A+B"` for several), `column_sizes(structure)`, and `forward_trace(model, X)`, which gives each column's post-activation values for a batch (element 0 is `X`). It is forward-only, so grads are untouched. `weights_of(model)` gives copies of `(W, b)` per Linear, `weights_from_arrays(structure, named_arrays)` builds the same from checkpoint-style `"0.weight"` keys, and `set_weights(model, weights)` writes them back. Not re-exported from `nn/__init__.py`, since it imports `nn.layers.linear`.
- **`model.py`** — `Sequential(Module)`: `__init__(self, *layers)` registers each positional layer under its index (`register_module(str(i), layer)`); `forward` just loops `self._modules.values()` in order and threads `x` through each layer, relying on `dict` preserving insertion order (Python 3.7+) to keep that order correct. Lets simple stacks (e.g. `Sequential(Linear(2,8), Tanh(), Linear(8,1), Sigmoid())`) skip writing a one-off `Module` subclass.
- **`activations/`** — `Activation(Module)` base class + `ReLU`, `Sigmoid`, `Tanh`, `Softmax`, each a thin wrapper calling the corresponding `Tensor` method (`x.relu()`, etc.) and storing `self.output`.
- **`losses/`** — plain (non-`Module`) `Loss` base class with `forward(y_pred, y_true)`; `MSE` composes existing `Tensor` ops (`(y_pred - y_true) ** 2).mean()`) so it gets autograd for free; `CrossEntropy` instead computes softmax+NLL directly in NumPy and wires a hand-derived fused backward rule (`backward_cross_entropy`) for numerical stability — these are two different, both-valid strategies for adding a loss (compose existing autograd ops vs. hand-derive a fused gradient), pick whichever fits a new loss's numerical stability needs.
- Note: `layers/__init__.py` and `losses/__init__.py` are empty (no re-exports), unlike `activations/__init__.py` and `optimizers/__init__.py` which do export their public classes. Import `Linear`/`MSE`/`CrossEntropy` via their full submodule path (`orbit.nn.layers.linear`, `orbit.nn.losses.mse`, ...) until that's made consistent.

### The data pipeline (`src/orbit/core/dataset.py`, `src/orbit/core/dataloader.py`)

- **`dataset.py`** — `Dataset` is a plain interface (no `abc`, matching the rest of the codebase): `__len__`/`__getitem__`/`input_shape`/`output_shape` all raise `NotImplementedError` on the base class. Contract: `__getitem__` returns one `(x, y)` sample as raw numpy (or scalars), **not** wrapped in `Tensor` — batching/`Tensor`-wrapping is `DataLoader`'s job, not `Dataset`'s. `TensorDataset(Dataset)` is the one concrete implementation: wraps two arrays (accepts numpy, lists, or `Tensor`s — unwraps `.data` if given a `Tensor`), validates matching row counts (`ValueError` if not), indexes both in lockstep, and exposes `input_shape`/`output_shape` as plain ints (`self.X.shape[-1]`/`self.Y.shape[-1]`, the per-sample feature count) — used by `core/config.py`'s `build_model` to validate a model's first/last `Linear` layer against the dataset it'll actually run on. `TensorDataset` itself never rescales anything (its `__init__` only coerces `Tensor`/list inputs to `np.ndarray`); input normalization lives in the same file as `fit_normalizer`/`apply_normalizer`/`NormalizedDataset`, a wrapper view applied by `load_experiment` when a config sets `"normalize"` — see "Planned: normalization, train/test split..." above (item #1). `dataset.py` also has `Subset(Dataset)` (a generic index-based view delegating `__len__`/`__getitem__`/`input_shape`/`output_shape` to a wrapped `Dataset` plus an index list) and `train_test_split(dataset, test_split) -> (Subset, Subset)`, which splits via `np.random.permutation` (drawing from the same global RNG `DataLoader`'s shuffle already uses) and raises `ValueError` if either resulting split would be empty — backs the `"test_split"` config field, see "Planned: normalization, train/test split..." above (item #2). `DataLoader` itself is unchanged: it always iterates whichever `Dataset`/`Subset` it's given, with no split awareness of its own — `load_experiment` builds two separate `DataLoader`s (train, test) off the two `Subset`s when a split is configured.
- **`dataloader.py`** — `DataLoader(dataset, batch_size=32, shuffle=True)`. `__len__` is `math.ceil(len(dataset) / batch_size)`. `__iter__` is a **generator** (has to be, not a method that builds and returns a list) — that's what makes every fresh `for X_batch, Y_batch in dataloader:` loop (i.e. every epoch) reshuffle independently rather than replaying the same order forever. Per batch: gathers `dataset[i]` for each index in the chunk, `np.stack`s the x's and y's separately, wraps both as `Tensor` — this is the one place in the pipeline where raw numpy becomes a `Tensor`. The last batch of an epoch is naturally short when the dataset doesn't divide evenly by `batch_size`; no special-casing needed, plain slicing handles it.

### The training layer (`src/orbit/nn/optimizers/`, `src/orbit/nn/training/`)

- **`optimizers/optimizer.py`** — `Optimizer` base class: `__init__(self, parameters, lr=0.01)` stores the parameter list and learning rate; `step()` raises `NotImplementedError`; `zero_grad()` sets every parameter's `.grad` to `None`. `Module.zero_grad()` does the same thing independently — call whichever one you already have a handle on.
- **`optimizers/sgd.py`** — `SGD(Optimizer)`, `SGD(parameters, lr=0.01, momentum=0.0)`: with `momentum == 0`, `step()` does plain `param.data -= self.lr * param.grad` (kept as its own branch so existing configs produce bit-identical results); otherwise it keeps a lazily-created per-parameter velocity (PyTorch convention: `v = momentum * v + grad; param -= lr * v`). Parameters whose `.grad` is `None` are skipped either way.
- **`optimizers/adam.py`** — `Adam(Optimizer)`, `Adam(parameters, lr=0.001, betas=(0.9, 0.999), eps=1e-8)`: per-parameter first/second moment estimates `m`/`v` with bias correction (`m / (1 - beta1**t)`, `v / (1 - beta2**t)`), update `param -= lr * m_hat / (sqrt(v_hat) + eps)`. State (`self.m`/`self.v`/`self.t`) is keyed by position in `self.parameters`, and the step count `t` is per parameter, so a parameter skipped because its `.grad` is `None` doesn't have its bias correction advanced. The class docstring derives the bias correction — keep it as teaching material.
- **`training/trainer.py`** — `Trainer.fit(model, loss_fn, optimizer, dataloader, epochs, verbose=False, log_every=100, accuracy_fn=None)` consumes a `DataLoader`: per epoch it loops every batch doing `model.zero_grad()` → `loss.backward()` → `optimizer.step()` (zero_grad happens **per batch**, not per epoch, so gradients never leak across batches), and accumulates a `batch_size`-weighted running sum to compute a true epoch-average loss (a plain float/numpy scalar, not a `Tensor` — you can't return a single `Tensor` representing an epoch once several batches' graphs have each already been consumed by their own `.backward()` call). If `accuracy_fn` is given (a `(y_pred, y_true) -> float` callable, e.g. `core/metrics.py`'s `accuracy`/`accuracy_multiclass`, resolved from a config's `"task"` field via `core/config.py`'s `TASK_REGISTRY`/`build_accuracy_fn`), every batch's predictions and targets are collected and `accuracy_fn` is called **once** on the whole epoch (`_whole_pass_metric`), not averaged per batch — required for R², which isn't a per-sample average (see "Planned..." item #4). The per-batch loop lives in a private `_run_epoch(model, loss_fn, optimizer, dataloader, accuracy_fn=None) -> (avg_loss, grad_norm, avg_accuracy)` helper, called once per epoch by `fit()` — it also computes `grad_norm` via the module-level `_gradient_norm(model)` helper (L2 norm of every parameter's gradient, flattened and concatenated, skipping parameters whose `.grad` is `None`) *after* `optimizer.step()` for that epoch's last batch, so it reports that last batch's gradient norm specifically, not a running average across the epoch — the standard signal for spotting vanishing/exploding gradients, not epoch-precise but cheap and directionally useful. `fit` returns the final epoch's average loss; `Trainer` also keeps three parallel per-epoch histories for anything that wants the full curves (e.g. `Experiment`/`Results` below): `self.history` (loss, always), `self.gradient_norm_history` (always), and `self.accuracy_history` (only initialized to a list, and only appended to, when `accuracy_fn is not None` — stays `None` otherwise, matching `Results.accuracy_history`'s optionality). `fit` also times the whole call with `time.time()` and stores the elapsed wall-clock seconds on `self.duration_seconds`. When `verbose=True` and stdout is a real terminal (`orbit.ui.is_tty()`), `fit()` renders a live `rich.progress.Progress` bar (percentage, epoch count, current loss, elapsed/remaining time) instead of printing — `log_every` is a no-op on that path since the bar updates every epoch. When output isn't a real terminal (piped, redirected to a file, or running under `pytest`), the original `print(f"{e} | {avg_loss}")` behavior (gated by `log_every`) is unchanged — this is why `tests/integration/test_xor.py`'s `verbose=True` run is unaffected. `Trainer.evaluate(model, loss_fn, dataloader, accuracy_fn=None) -> (loss, accuracy)` is the forward-pass-only counterpart to `fit()` — no `zero_grad()`/`backward()`/`optimizer.step()`, brackets the pass in `model.eval()`/`model.train()`, mirrors `_run_epoch`'s batch-weighted loss averaging and whole-pass accuracy metric. Built for `Experiment.run()`'s post-training test-set pass (see "Planned: normalization, train/test split..." above, item #2, now implemented) and reused as-is by the standalone `orbit test` command (item #3, also implemented). Like `fit()`, `evaluate()` renders a live `rich.progress.Progress` bar when stdout is a real terminal (`orbit.ui.is_tty()`) — via a private `_evaluate_with_progress_bar` helper mirroring `_fit_with_progress_bar`'s style (same `#ffeab0` "Evaluating" label, bar, elapsed/remaining time) — except gated on `is_tty()` alone rather than a `verbose` flag (`evaluate()` has no such parameter; every call wants the bar when interactive) and tracking *batches* rather than epochs, since a single evaluation pass has no epoch loop to report progress against; `evaluate()` has no non-progress-bar `print()` fallback the way `fit()` does, since it's only ever called after training already finished (nothing incremental worth logging to a non-tty stream). Both branches are functionally identical, just with/without the bar — `is_tty()` returning `False` under `pytest`'s `capsys` means existing tests exercise the plain loop unchanged.

### Experiment orchestration (`src/orbit/core/experiment.py`, `src/orbit/core/results.py`)

- **`results.py`** — `Results` is a plain, dependency-free data container (no imports from the rest of `orbit`, deliberately, since it's meant to be the thing a future `storage/` layer serializes): `name`, `final_loss`, `loss_history`, `hyperparams` (defaults to `{}`), plus `duration_seconds`, `gradient_norm_history`, `accuracy_history`, `test_loss`, and `test_accuracy` (all `Optional`, default `None` — `accuracy_history` stays `None` unless the experiment's config set a `"task"`, and `test_loss`/`test_accuracy` stay `None` unless it set `"test_split"`). `to_dict()`/`from_dict()` round-trip all of these through plain JSON-safe Python types (casting numpy scalars to `float`), including `None` for the optional fields, so `storage/experiments.py`'s save/load round trip already covers them with no extra work needed there.
- **`experiment.py`** — `Experiment(model, loss_fn, optimizer, dataloader, epochs, name=None, verbose=False, log_every=100, accuracy_fn=None, test_dataloader=None)` stores all of that plus its own `Trainer()` instance. `run(self)` (no extra args — everything needed is already on `self` from `__init__`) calls `self.trainer.fit(..., accuracy_fn=self.accuracy_fn)`, then, if `test_dataloader` was given, calls `self.trainer.evaluate(self.model, self.loss_fn, self.test_dataloader, accuracy_fn=self.accuracy_fn)` for a post-training test-set pass; both results are packaged into a `Results`, pulling `loss_history`/`gradient_norm_history`/`accuracy_history`/`duration_seconds` straight off the `Trainer` instance and building `hyperparams` from values already sitting on the objects it holds (`optimizer.lr`, `dataloader.batch_size`, `loss_fn.name`) rather than duplicating any of that state itself. `test_loss`/`test_accuracy` stay `None` when no `test_dataloader` is given — see "Planned: normalization, train/test split..." above (item #2) for how `core/config.py`'s `load_experiment` builds and passes one.

- **`ranking.py`** — ranking rows (plain dicts, each metric stored under its own name) by one or several metrics, shared by `orbit compare --by` and `orbit sweep compare --by`. `RANK_METRICS` maps each metric to "min"/"max" (`final_loss`, `test_loss`, `duration_seconds` lower-is-better; `accuracy` = final-epoch training accuracy/R², `test_accuracy` higher-is-better). Metrics have incompatible scales, so they are combined by **average rank**, not by adding values: `metric_ranks` ranks each metric (1 = best; ties share the average of the ranks they span, so 0.1, 0.1, 0.3 → 1.5, 1.5, 3; None/NaN → no rank), and `overall_ranking` orders by the mean of those ranks. Rows missing any chosen metric are "incomplete" and sorted after all complete rows, since an average over fewer metrics isn't comparable. Exact ties on average rank are broken by the per-metric ranks in the order the metrics were given. `usable_metrics` drops metrics no row has. The display side (colors, `★`, "Best …" lines, the metric checkbox) lives in `cli/commands/ranking_display.py`. Its `METRIC_COLORS` are deliberately more saturated than the rest of the pastel palette: pastels collapse together when a terminal downgrades to 256/16 colors, and `tests/cli/test_ranking_display.py` checks that they stay distinct from each other and from the overall-best green in truecolor, 256- and 16-color modes.
- **`metrics.py`** — plain functions, not classes (no autograd needed on final predictions): `accuracy(y_pred, y_true, threshold=0.5)` for binary classification, `accuracy_multiclass(y_pred, y_true)` using `np.argmax(y_pred.data, axis=-1)` vs. integer class labels. Plus two regression metrics: `regression_tolerance(y_pred, y_true, tolerance=0.5)` and `r2_score(y_pred, y_true)`, and two display helpers, `metric_label(task)`/`format_metric(value, task)`, so R² is never shown as a percentage. All are wired into `Trainer`/`Experiment`/`Results` — an experiment config's optional `"task"` field resolves through `core/config.py`'s `TASK_REGISTRY` to pick one as `Trainer.fit`'s `accuracy_fn`. See "Planned: normalization, train/test split..." above (item #4) for the design.

### Visualization (`src/orbit/visualization/`)

- **`loss.py`** — `plot_loss(results: Results, output_path: pathlib.Path, log_scale: bool = False) -> pathlib.Path`: renders `results.loss_history` as a `matplotlib` line plot (epoch on the x-axis, loss on the y-axis, `#b0ffb3` accent color, titled `f"{results.name} — Training Loss"`, `" (log scale)"` appended when `log_scale=True` alongside setting `ax.set_yscale("log")`) and saves it as a PNG at `output_path`, returning that path. Raises `ValueError` if `loss_history` is empty. `plot_loss_comparison(results_list: List[Results], output_path, log_scale=False) -> pathlib.Path` overlays several `Results`' loss curves on one plot instead of just one, each labeled by `results.name` via `ax.legend()`, using per-line colors from `comparison_style.line_colors` (not a fixed accent color, since a single fixed color can't distinguish multiple lines) — backs `orbit compare --plotloss`, `orbit plot`'s `loss` metric and `orbit sweep plot`. Both import `matplotlib` lazily inside the function (not at module scope) and force the non-interactive `Agg` backend before importing `pyplot` — see `cli/commands/plotloss.py`'s doc note above for why.
- **`accuracy.py`**, **`gradients.py`** — same shape as `loss.py`, one function pair each: `plot_accuracy`/`plot_accuracy_comparison` (`results.accuracy_history`, raw values; y-axis/title from `accuracy_axis_label`, i.e. "Accuracy" or "R²" by each experiment's `hyperparams["task"]`, "Accuracy / R²" when mixed) and `plot_gradient_norm`/`plot_gradient_norm_comparison` (`results.gradient_norm_history`, y-axis "Gradient Norm"). Same `ValueError`-on-empty-history guard, same lazy `matplotlib` import.
- **`comparison_style.py`** — shared by all three `*_comparison` line plots (and, for bar layout, by `test_metrics.py` below), so that a large comparison (a sweep easily has 10–50 runs) doesn't end up with a legend covering the curves and repeating colors. `line_colors(n)`: `None` (matplotlib's default 10-color cycle) up to 10 lines, `tab20` up to 20, then evenly spaced samples of `turbo`. `add_legend(ax, n)`: matplotlib's default in-plot legend up to `INSIDE_LEGEND_MAX = 6` lines, otherwise placed outside the axes to the right, split into a new column every 20 entries (`legend_columns`). So comparisons of up to 6 lines look exactly as before. The comparison functions save with `bbox_inches="tight"` so the outside legend isn't cropped. See `tests/visualization/test_comparison_style.py`.
- **`test_metrics.py`** — `plot_test_loss`/`plot_test_accuracy(results_list: List[Results], output_path, log_scale=False) -> pathlib.Path`: **bar charts**, not line plots, since `test_loss`/`test_accuracy` are single scalars per experiment, not per-epoch histories — one bar per `Results` in `results_list` (always a list, even for a single experiment, unlike `loss.py`'s single/comparison split — a bar chart already generalizes from 1 to N bars with the same code shape). Both delegate to a shared private `_bar_chart(...)` helper. Up to `comparison_style.VERTICAL_BARS_MAX = 6` bars it draws vertical bars (`ax.bar(names, values, color="#b0ffb3")`, names rotated with `fig.autofmt_xdate(rotation=30)`). Past that, e.g. a sweep's runs, rotated names overlap and get cropped, so it switches to horizontal bars (`ax.barh`): names down the y-axis with the first experiment at the top (`invert_yaxis`), each bar labeled with its value (`ax.bar_label`, `.4g`), `--logscale` applied to the x (value) axis, and a figure height that grows with the bar count (`comparison_style.bar_figure_height`). Both layouts save with `bbox_inches="tight"` so long names aren't cropped. Raises `ValueError` on an empty list.
- **`network.py`** — network diagrams. `draw_network(ax, structure, weights, activations, value_ranges=None, weight_scales=None, ranked_nodes=None)` only draws onto an Axes, so later animation phases can redraw it per frame; `plot_network(...)` is the PNG wrapper (`bbox_inches="tight"`, dpi 150, optional `subtitle`/`show`).
  - **Edges**: an `RdBu_r` color for the weight sign (red +, blue −). Thickness and opacity scale with `|w|` / the layer's max `|w|`. Drawn as one `LineCollection` per layer.
  - **Nodes**: `magma` fill for the activation, normalized per column (ReLU and Sigmoid columns live on different scales) against `value_ranges` when given. The outline is the unit's bias on the edge scale (grey for inputs). Values are printed inside nodes when a column shows 12 or fewer.
  - **Wide columns**: a column with more than `MAX_NODES_PER_COLUMN = 16` nodes shows 15 of them plus a `⋮ +k` marker. With `ranked_nodes` (from `rank_nodes(trace)`, by mean `|activation|`), it shows the top 15 in index order with the marker at the bottom, because in a 128-unit ReLU layer an arbitrary first/last 15 are mostly silent units. Without it, it shows the first 8 and last 7.
  - **Legend**: two horizontal colorbars sit under the diagram in axes coordinates, since vertical ones overlapped next to the aspect-locked axes.
- **`backend.py`** — `pyplot(show)` imports pyplot on Agg, or TkAgg for `--show` (falling back to Agg with a warning), and `can_show(plt)`. Only the new visualization commands use it; the older modules keep their own inline Agg code.
- `visualization/__init__.py` exports all of the above (`from .loss import ...`, `from .accuracy import ...`, etc.), matching the export convention every other `nn/*/__init__.py`-style package in this codebase already uses. `weights.py`/`terminal.py` are still empty stubs — nothing tracks weight history yet, and `terminal.py`'s ASCII/terminal-rendered-plot purpose (distinct from `matplotlib`-to-PNG) isn't part of any planned work yet.

## Conventions to follow

- Match the existing style: heavy docstring/comment explanations of the *math* in `core/` (why a gradient rule is what it is), sparser comments in straightforward `nn/` wrapper code.
- New `Tensor` operations follow the established pattern: build the output `Tensor` with `operation=` and `parents=` set, then attach `out._backward = lambda res=out, ...: backward_<op>(res, ...)`, and add the corresponding `backward_<op>` function in `autograd.py`.
- New losses/activations/layers follow the existing base-class shape (`Loss`, `Activation`, `Module`) in their respective `__init__.py`-exported package.
- Test philosophy (see `tests/core/test_autograd.py`): small, single-purpose tests, each with a comment deriving the expected gradient by hand before asserting `np.allclose(...)`. Follow this for new autograd rules — a numerical/hand-derived check, not just a smoke test.
- Don't add broadcasting, shape-inference magic, or other generalizations beyond what the current op needs unless asked — v0.1 intentionally assumes compatible shapes. `backward_add`'s `unbroadcast` is the sole, deliberate exception (needed for `Linear`'s bias term); it is not a precedent for generalizing other ops without being asked.
